# ADR 0040: 操作固有設定をワークフロー内へ配置する

## 状態

採用

## 決定

常時表示するUIは、現在の編集状態、頻繁に切り替えるモード、Undo／Redoなどアプリ全体に作用する操作に限定する。

入出力形式、入力単位、入力ファイルのUp軸、非表示Objectを出力へ含めるかなど、特定操作でしか使わない設定はヘッダーや常設パネルへ置かない。操作の入口を選んだ後に開くダイアログ、ポップオーバー、または段階的なパネル内へ配置する。

ファイル処理のワークフローは次の状態を一つの画面内で扱う。

1. 実行前の形式・オプション確認
2. ファイル選択または実行
3. 実行中の進捗とキャンセル
4. 成功時の結果概要、または回復可能なエラー通知

設定値は次回操作の初期値として保持してよいが、設定コントロール自体を常時露出させる理由にはしない。複数形式が同じ目的を持つ場合は、ヘッダーの入口を一つにまとめ、形式選択をワークフロー内へ移す。

新しい常設コントロールを追加する際は、次を確認する。

- その設定は複数機能へ継続的に影響するか
- 編集中に頻繁な切替が必要か
- 現在値を常に把握する必要があるか
- 操作開始後の提示では手遅れになるか

すべて「いいえ」であれば、原則として操作固有UIへ配置する。

## 理由

特定機能の設定を常時表示すると、画面幅を消費し、設定の作用範囲が不明瞭になり、主要な編集状態との優先順位も崩れる。必要になった時点で関連設定、進捗、結果をまとめて提示することで、ヘッダーを安定させ、誤解と操作漏れを減らす。

## 適用例

- `3D読込`: 入力単位とUp軸を指定してからファイルを選択する
- `3D出力`: GLB／STL／OBJと非表示Objectを含めるかを指定してから書き出す
- Booleanやメッシュ修復で将来詳細設定を増やす場合: 操作ボタンの近くへ常設せず、実行ダイアログへまとめる
