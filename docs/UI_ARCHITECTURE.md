# UIスタイル設計

## 目標

UIはデザイントークン、共通プリミティブ、Tailwindユーティリティの3層で構成する。Canvas、複雑なオーバーレイ、ブラウザ固有表現だけをセマンティックCSSに残す。

## レイヤー

1. `src/styles/design-system.css`: 色、余白、文字、角丸、影、モーションの基準値。
2. `src/index.css`: トークンをTailwindテーマへ公開し、アプリ全体の最小限のルート設定を行う。既存画面への破壊的変更を避けるためPreflightは使わない。
3. `src/ui/primitives`: ButtonやControlGroupなど、状態と見た目を統一するUI部品。
4. コンポーネント内Tailwind: レイアウトと、その場所だけに必要な装飾。
5. `src/App.css`: アプリシェル、Canvasオーバーレイ、複雑なフォーム配置などのセマンティックスタイル。

## 規約

- 色や影の値をコンポーネントへ直書きせず、Tailwindテーマ名またはデザイントークンを使う。
- 同じボタン表現を2回以上使う場合は`Button`のvariantへ集約する。
- 操作群には常に可視ラベルを付け、無効条件はラベルまたは`title`で説明する。
- `active`、`disabled`、`focus-visible`を共通部品で扱う。
- CSSはDOM構造へ過度に依存するセレクターを避ける。
- 変更時は1440×900相当の全体画面と、対象パネルの選択・無効状態を画像で確認する。
